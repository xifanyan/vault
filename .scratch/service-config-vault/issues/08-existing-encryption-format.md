## Question

是否存在能直接复用的成熟加密文件容器，满足本项目的可移植口令加密、Go 直接集成、完整载荷保密及认证失败不返回配置的要求，从而避免自行设计加密封装？

以 age 的正式格式规范、官方 Go 库文档和源码为主要候选，核查口令模式、实际密码组成、认证范围、流式读取何时完成验证、盐和随机量处理、工作因子与解密资源上限接口、格式识别、载荷以外可见信息、许可及兼容性边界。

指出它与已确认 UTF-8 口令规则、配置和敏感元数据一同加密、有限文件大小和输入认证要求的适配点及缺口。不得把算法文档、库保证和未经执行的跨平台行为混为一谈；每项事实引用第一方来源，不替用户作产品取舍。

## Answer

已完成[带第一方引用的 age 容器研究](../research/existing-encryption-format.md)。age v1 与官方 Go 库可复用，但应用必须限制输入和 KDF 成本、完整读取并认证后才返回配置；其自动化口令模式警示、公开长度边界及版本要求均已记录。

集成者另在 Windows/amd64、Go 1.27.2、age v1.3.2 上运行库级烟测，验证正常往返、错误口令、末块篡改、截断及工作因子上限，并观察到部分明文可先于最终错误返回。结果见同一研究文档，不代表产品或跨平台验收完成。

按用户明确批准采用本地 Markdown 交付，不创建或推送研究分支。产品方案由加密封装决策票据单独确认。
