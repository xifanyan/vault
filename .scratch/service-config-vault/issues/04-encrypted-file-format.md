## Question

在可移植口令加密、认证失败必须终止、格式版本不等于配置历史的已确认边界内，选择什么密码与文件协议，才能安全保存配置值和敏感元数据，并在三个操作系统间交换？

需要与用户确定并由 agent 提供事实依据：

- 成熟的认证加密、口令派生方案与库；结合目标启动成本确定参数，而非自行设计密码算法或直接把未经核实的参数当作结论。
- 格式标识、版本、盐、随机量、口令派生参数和加密载荷的布局，哪些头部字段受到认证保护。
- 配置和敏感标记如何序列化为载荷，哪些信息可以出现在未加密头部。
- 文件大小与派生参数上限，以及认证前解析时的资源限制。
- 未知格式、错误口令、截断和篡改文件的失败契约；格式兼容与显式转换策略，不加入配置历史。

本票为 HITL 的方案决策；事实依据来自已完成的研究票据和注明范围的库级运行观察，不把库级烟测等同于产品验收。

## Answer

### 选定的加密封装

复用原生二进制 age v1 文件及官方 Go 库，参考集成版本为 `filippo.io/age v1.3.2`。不另加外层加密协议，不提供 ASCII armor、机器密钥、插件或多收件人模式；本产品不是通用 age 解密器。

只接受唯一的 scrypt 口令 stanza。按 age v1 协议，由 scrypt 派生包封密钥、ChaCha20-Poly1305 保护文件密钥与分块载荷、HMAC-SHA-256 认证头部；随机文件密钥、盐、载荷 nonce 和块计数由官方实现负责，不自行复刻原语组合。完整协议事实及来源见[容器研究](../research/existing-encryption-format.md)。

每次生成或重新加密文件均调用正常 age 加密流程，使用新的随机材料；只复制已有文件不等于重新加密。更换口令须先完整解锁原文件，再以新口令生成完整新密文，成功完成写端关闭后才交给既定文件替换流程。

### 固定成本与可见信息

写入固定 `logN=18`，即 `N=2^18, r=8, p=1`。读取也只接受此档位：派生前检查唯一 scrypt stanza 及工作因子恰为 18，并显式调用 `SetMaxWorkFactor(18)`；只设置最大值不足以拒绝更弱档位。未知、较低或较高档位均失败，不自动协商、降级或重试。

scrypt 的主工作区约 256 MiB，另有少量辅助分配；这符合用户确认的“约”预算，不是严格的进程总内存或 RSS 上限。并发解锁会叠加开销。约 1 秒是参考主机目标，不是超时或速度保证；用户在看到当前主机单次观察后仍选择保留该档位，不因运行缓慢自动降低成本。

接受格式标识、公开盐、工作参数和可推导的载荷长度可见，不加入长度填充。服务标识、环境名称、配置值与完整分类表均属于加密载荷，不放入明文头部。

age 官方建议自动化系统优先使用机器密钥；用户知情后保留已确认的口令模式。按最新便携目标，独立口令文件可迁移到其他主机，部署方负责安全传输和保管，不将口令嵌入 vault。该使用方式仍不描述为上游推荐的自动化方案，也不声称 FIPS 认证。

### 严格的载荷 schema v1

加密载荷是恰好一份无压缩、有效 UTF-8 JSON 对象，不接受 BOM、第二个尾随 JSON 值、重复字段或以替换字符修复非法输入。它不是供查看的脱敏导出，也不承担 JSON 导入/恢复协议职责。

外层必须且只包含以下字段；配置对象内部的合法用户键不受这些字段名限制：

| 字段 | v1 要求 |
| --- | --- |
| `schema_version` | JSON 整数 `1`，只描述载荷协议，不表示配置历史 |
| `service` | 非空服务标识字符串；一个载荷对应一个服务 |
| `defaults` | 服务默认配置对象 |
| `environments` | 环境名称到覆盖对象的映射；名称遵循已确认的命名规则 |
| `classifications` | 逻辑配置 JSON Pointer 到 `sensitive` 或 `non-sensitive` 的映射 |

分类路径相对于默认配置或环境配置的逻辑根，不带 `defaults` 或环境名前缀；分类在各环境间共享。所有现存且可沿对象成员寻址的配置节点均需有分类记录，配置根和数组内部不要求单独记录；不把缺少现存节点分类当成普通配置。写入自动创建的中间结构时，仅对原先未分类的结构节点记录 `non-sensitive`，不覆盖保留的敏感标记；新增目标及新增后代按既定默认敏感规则记录分类。

分类表允许保留当前没有值或因类型遮挡而不可达的合法路径，不能因解析当前配置而剪掉这些标记。路径语法、大小写与 Unicode 匹配、数组整体分类、父级遮挡和取消标记行为沿用已解决的两张语义票据，不在文件解析中重新解释。

未知外层字段、未知 schema 版本、未知分类值及无法按既定语义解释的结构均失败。只支持当前协议，不猜测旧格式、不自动迁移或回退；将来变更须明确新版本及其兼容决策。

### 有界读取与完整认证

| 资源 | 本协议边界 |
| --- | --- |
| 实际加密文件字节 | 最多 20 MiB，不能只信任文件头或预先获得的文件大小 |
| 完整解密载荷字节 | 最多 16 MiB，包含服务标识、配置、分类与 JSON 编码开销 |
| 头部解析 | 参考 age v1.3.2 的 2 MiB 头部硬上限；它不是整个文件或 KDF 上限 |
| JSON 嵌套 | 对象和数组最多 64 层，载荷外层对象记为第 1 层 |
| 分类路径 | 最多 64 段，按 JSON Pointer 的对象成员段计数 |

先使用有界输入并检查支持的格式与 stanza 档位，再进行有上限的口令派生。库升级必须重新核对头部上限、成本控制接口和完整读取行为，不能默默沿用未经核查的新默认值。

解密得到的明文只在调用方不可见的有界内存中暂存，不写入明文临时文件。必须读至真实 EOF，确认所有块及末块认证成功、无截断或尾随数据错误后，再完整校验 JSON、schema、分类、层数和路径限制，最后一次性交付配置。

超限检测应能区分真实 EOF 与限长读取制造的 EOF；不得把截断前的内容当作成功。任何阶段失败均丢弃内部结果，不返回部分配置、空配置替代物或将 age 的惰性 Reader 直接交给业务调用方。错误输出不得回显口令、载荷内容或隐藏的内部路径。

### 证据与剩余边界

事实依据为[成熟容器研究及 Windows 库级烟测](../research/existing-encryption-format.md)和[Go 原语与资源模型研究](../research/go-crypto-resource-limits.md)。库级烟测实际覆盖正常往返、错误口令、末块篡改、截断和解密工作因子上限；没有验证本产品的 schema、完整快照交付、应用大小上限、并发内存或三平台运行。

研究引用的 age v1.3.2 模块声明 Go 1.25.0，发布构建工具链声明为 Go 1.27.0；本次实际运行使用 Go 1.27.2。这些事实不能推成全平台验收。最新文件使用边界见[便携使用契约](05-file-operations.md#answer)；不再为本项目另建文件系统强保证矩阵。
