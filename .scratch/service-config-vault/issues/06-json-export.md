## Question

在已确认默认脱敏、明文敏感值必须显式选择、JSON 不承担可恢复备份职责的前提下，导出应提供什么视图与结构，才能便于查看而不混淆存储值和有效值？

需要与用户确定：

- 支持某个环境的有效配置、保存的默认值与覆盖层，还是两种视图；如何显式选择环境和视图。
- 导出 JSON 的外层结构及脱敏标识，确保真实值不会与占位符混淆，并与已确定的敏感标记规则一致。
- 标准输出和输出文件的行为、目标已存在时的策略，以及明文敏感值的显式选择和提示方式。
- 用继承值、显式 `null`、数组和敏感值的例子说明输出；口令及加密密钥始终不进入导出内容。

本票确定导出结果与安全交互，命令拼写在接口票据中统一；不增加 JSON 导入或备份恢复。

## Comments

用户选择整库层级配置作为唯一导出视图，并确认标准输出默认、显式文件输出默认不覆盖；其余行为沿用已批准的安全规则及简单 CLI 惯例，不新增导出模式。

## Answer

### 导出的内容

仅导出服务默认值与各环境覆盖的原始层级，不将默认值合并进环境层，不提供单环境有效配置导出模式。Go `ExportJSON` 反映当前内存模型，包括尚未 `Save` 的修改；CLI 每次重新打开磁盘文件导出。这里的层级与有效配置之别不因内存编辑而改变。

保留 JSON 值类型、数值精度和数组内容；缺失的覆盖键仍缺失，显式 `null` 仍为值。导出只供查看，不是内部加密载荷、可恢复备份或 JSON 导入格式，不附带内部分类表、解锁凭据或加密密钥。

### 输出结构与脱敏位置

输出包含三个外层字段：

| 字段 | 含义 |
| --- | --- |
| `service` | 当前 vault 的服务标识 |
| `data` | 包含 `defaults` 和 `environments` 的层级配置；按各存储层分别脱敏 |
| `redacted_paths` | 指向 `data` 内已隐藏节点的 JSON Pointer 字符串数组，无隐藏节点时为 `[]` |

`redacted_paths` 相对于 `data`，不是相对于整个输出对象，也不是直接输出内部的逻辑分类表。例如默认层的敏感键 `/database/password` 对应 `/defaults/database/password`；环境中的保护边界加上 `/environments/<环境名>` 前缀。用户键中的 `/` 和 `~` 按既定 JSON Pointer 规则转义。

隐藏值写为 `null`；普通真实 `null` 无脱敏路径标记，敏感值即使原本就是 `null` 也记录边界。敏感对象或数组整体隐藏，只记录最外层保护边界，不列出子结构；对当前层不存在的键不创建值或脱敏路径。环境层中发生父级类型遮挡时，沿用敏感性票据的父级整体隐藏规则。

只有用户显式选择包含敏感值时才输出真实值，此时不放脱敏占位符，`redacted_paths` 为 `[]`。该选择不触发额外确认提示，也不改变 vault 中的分类或配置。帮助与文档明确说明明文输出不受 vault 加密保护；JSON 中不混入提示文本。

### 示例

本例的 `/database/password` 为敏感，其余出现的配置键均已显式设为普通。生产层只覆盖 host 和数组，未保存 password、timeout 或 nullable 的覆盖值；因此不会在生产层补出这些默认值。

```json
{
  "service": "example-service",
  "data": {
    "defaults": {
      "database": {
        "host": "localhost",
        "password": null
      },
      "timeout": 30,
      "nullable": null,
      "servers": ["a", "b"]
    },
    "environments": {
      "prod": {
        "database": {"host": "db.prod"},
        "servers": ["prod-a"]
      }
    }
  },
  "redacted_paths": ["/defaults/database/password"]
}
```

示例展示输出格式，不表示已实现或运行导出功能。内部分类表不作为额外元数据输出；用户自己的配置键若恰好叫 `classifications`，仍按普通配置数据与敏感性规则处理。

### 输出文件与错误

未指定文件时向标准输出写可读 JSON，诊断仅写标准错误。采用两空格缩进并以换行结束，不添加进度、提示或日志。CLI 使用 `export`、`--output`、`--overwrite` 和 `--include-secrets`，完整调用方式见[接口契约](07-cli-go-contract.md#answer)。

指定输出文件时默认拒绝覆盖，只有显式覆盖选择才替换已有文件；即使允许覆盖，也不得将工具自己打开的输出目标指向本次输入 vault 或凭据文件，包括可识别为同一文件的别名。操作者继续遵循串行修改与复制边界，不新增锁或文件系统事务。

先完整解锁、验证并准备输出，再创建或修改输出文件。因此认证、载荷验证或序列化失败时，标准输出没有 JSON 内容，既有输出文件不被改动。实际输出 I/O 失败必须返回错误，不宣称成功；已经写出的标准输出字节无法撤回，输出文件也不承诺事务恢复。

覆盖检查只约束工具自己管理的文件路径。shell 重定向在程序运行前由 shell 处理，不能承诺保护被重定向覆盖的文件；不得把它指向 vault 或凭据文件。

本票不新增产品实现、JSON 导入、备份恢复、单环境导出或复杂文件协调。导出行为与最终接口已衔接，实际代码和运行验收仍待实现阶段执行。
