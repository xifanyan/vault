# 本地服务配置 Vault：设计规格

## 文档状态与目标

本文记录当前简化范围内已确认的配置、凭据、文件、导出及 CLI/Go 接口决策。实现已合并至 `integration/service-config-vault`，并在 Windows/amd64、Go 1.27.2 上通过 Go 测试与 CLI smoke；Linux/macOS 实机验收尚未执行。

目标是使用 Go 提供可在 Windows、Linux、macOS 上运行的配置管理 CLI，以及可程序化读写本地 vault 的 Go 库。

最新优先级是可复制性：将加密 vault 与独立解锁凭据文件复制到另一主机后，兼容的 CLI 或 Go 程序可以打开并得到相同配置。不为此建立复杂文件协调或部署协议；解锁凭据先沿用现有口令文件，不切换加密模式。

领域术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准。文档位置遵循[本地 issue tracker 约定](../../docs/agents/issue-tracker.md)。

决策结论见[已完成的路线图](map.md)和对应票据；当前范围已收敛，可进入实现，不把文件协调服务、安装注册或强文件系统事务作为前提。

## 已确认的产品范围

- vault 是可复制的本地加密文件，保存服务配置和敏感值，不依赖中央服务。
- 每个 vault 对应一个服务。同一服务可按信任范围使用不同 vault，例如开发和生产分开存放。
- 文件与独立解锁凭据可手动复制到不同主机；同一份逻辑 vault 同一时间只在一台主机编辑，同一副本的修改和复制由操作者串行安排。
- CLI 提供 `init`、`env list/create/delete`、`get`、`set`、`delete`、`classify`、`export` 和 `passwd`；完整参数与行为见[CLI 与 Go 库接口契约](issues/07-cli-go-contract.md#answer)。
- Go 库公开初始化、读取和写入能力，使用内存模型及显式保存；不提供 HTTP API。
- 配置层级为服务默认值、环境覆盖和配置键；不加入主机级配置。
- 文件通过口令加密，复制后可在另一受支持操作系统上使用同一口令解锁。
- JSON 用于查看，默认隐藏敏感值；显式选择后可导出明文敏感值。
- 不保留配置版本历史，不提供回滚。

## 安全边界与分发

### 环境不是访问权限

持有 vault 文件和正确口令，即具有读取该文件内全部环境及敏感值的能力。环境选择和输出脱敏属于使用行为，不是授权隔离。

开发主机不应收到包含生产密钥的 vault。需要不同信任范围时，为同一服务分别维护只包含相应配置的 vault；分发单位仍然是整个文件，不假设支持按环境过滤生成新 vault。

### 口令与解锁

- CLI 的交互式口令输入隐藏回显。
- 自动化场景支持通过标准输入或受操作系统权限保护的口令文件提供口令，不将口令放入命令行参数。
- Go 文件式入口由调用方显式指定凭据文件位置，共用 CLI 的口令文件读取规则；解锁核心接收实际口令，不自行提示终端输入或隐式读取环境变量。
- 口令不写入 vault、代码、日志或导出的 JSON。独立凭据文件可复制到目标主机，由部署方保护其传输与存放；两份文件同时泄露即可解密。
- 部署方负责凭据保管；可编辑的 Go 对象仅在本进程内保留本次解锁材料以供保存，不建立系统钥匙链或跨进程凭据托管。
- 忘记口令无法恢复数据。若更换口令并重新加密文件，旧副本仍能被旧口令解锁，不能远程撤销。

已确认的操作契约见[口令输入与凭据生命周期](issues/03-passphrase-input.md#answer)。每份口令只允许隐藏终端、口令文件或标准输入中的一个来源；来源冲突或失败时不做优先级与回退。没有显式来源时，仅交互终端可以提示输入，无人值守场景直接失败。

一次操作的标准输入只能承载一个逻辑输入。CLI 当前来源为 `--passphrase-file`、`--passphrase-stdin`、`--prompt-passphrase`，新口令使用对应的 `--new-passphrase-file`、`--new-passphrase-stdin`、`--prompt-new-passphrase`，均互斥且不回退。

口令内容为有效 UTF-8，不接受 BOM，拒绝空值、多行和 NUL。CLI 与 Go 文件式入口共用适配规则：从文件只移除一个结尾的 LF 或 CRLF，保留其他前后空格，不做 Unicode 归一化；CLI 标准输入适配同理。解锁核心不再次裁剪实际口令，直接传入的多行口令仍失败。

新建或更换口令时，交互式新口令输入两次确认，自动化从显式来源读取一次，不追加提示。更换前必须验证旧口令；任何输入、来源或验证失败均不改动原 vault。普通文件写入边界见[便携使用契约](issues/05-file-operations.md#answer)；更换解锁口令不会改变其中的业务凭据。

`GenerateCredentials` 生成 32 个密码学随机字节，编码为无填充 base64url 单行并以 LF 结束；`init --generate-passphrase-file` 显式生成凭据再创建 vault。新文件不覆盖已有路径，不在读取失败后自动生成，也不宣称两份文件原子创建；I/O 失败可能留有文件，必须报告并由操作者核对。

### 加密与泄露边界

采用原生二进制 age v1 口令模式及官方 Go 库，参考版本 `filippo.io/age v1.3.2`。固定 scrypt `logN=18, r=8, p=1`，复用协议的密钥包封、ChaCha20-Poly1305 载荷认证及头部 MAC，不自行设计密码原语或加密封装。用户已知情接受上游对自动化口令模式的警示；详见[已确认的加密封装与文件格式契约](issues/04-encrypted-file-format.md#answer)。

加密用于保护静态文件并检测未通过认证的文件内容；它不能保护已解锁进程中的明文，也不能抵御已控制主机或已取得口令的攻击者。脱敏不是加密或访问控制。

不填充以隐藏长度；格式标识、公开盐和工作参数、可推导的载荷长度可见。服务标识、环境名称、配置值及完整分类表均放在密文中。部署方仍负责安全注入口令，不声称本方案获得 FIPS 认证。

## 配置模型与解析语义

### 默认值与环境覆盖

一个 vault 保存服务默认值和具名环境的覆盖值。调用方显式选择环境，再计算该环境的有效配置；未知环境必须报错，不能自动退回另一个环境。

默认配置和每个环境覆盖层的顶层都必须是 JSON 对象。环境名称满足 `^[a-z0-9][a-z0-9_-]*$`；默认配置使用独立作用域，不把任何环境名解释为默认配置的别名。

采用以下值与合并规则：

- 支持 JSON 的字符串、数值、布尔、对象、数组及 `null`，不是统一保存为字符串。
- 默认值与环境覆盖在同一路径均为对象时，按键递归合并。
- 其他情况由环境值整体替换默认值，包括数组和类型变化；数组不按位置或元素合并。
- 未被环境覆盖的键继承默认值。
- `null` 是显式配置值，不等同于缺失或删除。
- 删除环境中的覆盖后，重新继承该路径的默认值；此操作不用于屏蔽继承值。

例如，默认配置有 `database.host` 和 `database.port`，环境只覆盖 `database.host`，最终配置仍包含默认的 `database.port`。删除该环境的 host 覆盖后，host 恢复为默认值。

### 键路径与配置层写入

采用[配置键路径与 JSON 保真的已确认结论](issues/01-key-paths-json.md#answer)。路径使用 JSON Pointer 的字符串形式：`/database/host` 表示嵌套成员，`/database.host` 表示含点号的键；`~1` 和 `~0` 分别表示键名中的 `/` 和 `~`。空字符串键与 Unicode 键合法，按解码后的字符串精确匹配，不进行大小写折叠或 Unicode 归一化；非法指针及转义报错。

空指针 `""` 只允许读取根对象，不允许写入或删除根；`/` 寻址空字符串键，不是根。路径只沿对象成员寻址，数组只能整体读取和替换，不提供数组元素访问。

设置某一存储层的路径时，缺失的中间对象自动创建；已有中间节点为标量、`null` 或数组时必须报错，不隐式更改其类型。目标成员可以显式整体替换；失败不保存部分创建的父对象。冲突检查针对正在编辑的层，而不是合并后的有效配置；写入不修改配置快照。

### JSON 保真

JSON 数值在读取、修改和导出时保持精度，不默认经由 `float64` 转换；无法精确转换为调用方要求的 Go 类型时明确报错。不承诺保留原始空白或数字书写格式。

拒绝同一 JSON 对象中的重复键，按 JSON 字符串解码后的键比较；例如 `"a"` 与 `"\u0061"` 不能并存。不得默默使用最后一个值。

### 敏感性元数据

敏感标记绑定逻辑配置键，而不是仅绑定某个环境中存储的那份值。环境覆盖值时保留该键的敏感性，不能隐式取消标记。

此前没有分类的新配置值默认敏感，普通配置需显式声明；删除或替换值不取消已有敏感标记。恢复继承或重新写入同一路径后，标记继续生效。取消对象自身标记不递归取消子键标记；敏感祖先的保护不能由普通子键覆盖。

自动创建的中间对象只作为结构，不额外给整个分支标敏感；真正新增且未分类的目标值默认敏感。整体新增对象时，目标及新增后代键均默认敏感。数组整体分类，不创建元素级标记。

CLI 的普通读取、查看、错误输出及默认 JSON 导出使用一致的脱敏规则。新增或修改敏感值时提供不经命令行参数传值的输入方式，避免进入 shell 历史或进程参数列表。

例如，`/database/password` 已标记敏感，生产环境替换其值后仍必须隐藏；若该环境把 `/database` 改成字符串、`null` 或数组，从而遮挡敏感子路径，则在该视图中隐藏整个 `/database`。读取不新增父级标记，也不删除原子路径标记。

敏感容器整体脱敏，不泄露成员名称、数量或结构。合法路径请求进入受保护容器时，普通查看不进一步区分内部路径是否存在或类型是否匹配；显式明文查看及业务真实读取仍遵循正常寻址规则。完整结论与边界示例见[敏感标记与脱敏规则](issues/02-secret-metadata.md#answer)。

## Go 库与 CLI 的职责

解密、格式解析、层级合并和敏感性规则集中在同一个 Go 库中。CLI 只负责输入、输出及调用这些规则，不能另行实现一套合并或脱敏逻辑。

公共 Go 包提供 `GenerateCredentials`、`Create`、`Open`；`Vault`/`Layer` 支持环境管理、原值修改、删除和全局分类，修改先留在内存，`Save` 或 `SaveWithCredentials` 才写盘。CLI 一条修改命令只保存一次，初始化及更换口令不额外重复保存。完整签名见[接口契约](issues/07-cli-go-contract.md#answer)。

`Config` 是环境解析产生的独立快照，可并发只读；`Vault` 与 `Layer` 由调用方串行使用。内存修改、保存或磁盘更新不改变旧快照；重新打开取得文件更新，不自动热加载、合并或重试。

缺失环境或键返回 `ErrNotFound`，真实 JSON `null` 读取成功；其他公开错误为 `ErrInvalidArgument`、`ErrAlreadyExists`、`ErrAuthentication`、`ErrInvalidFormat`、`ErrLimitExceeded`，文件错误保留原生可检查关系。CLI 使用成功 `0`、调用形状错误 `2`、其他操作失败 `1`，不伪造空配置。

Go 的 `Layer.Get` 与 `Config.Get` 返回调用方拥有的真实 `json.RawMessage`，不暴露可修改的内部别名或做隐式数值转换；业务自行解码。CLI 普通查询另行遵循脱敏规则，固定返回 `value` 和相对所选配置根的 `redacted_paths`。

生成脱敏视图不得修改业务配置快照或持久化内容；普通查看的不透明行为不能变成业务真实读取的占位符或伪造成功。

## JSON 查看与导出

- 默认导出隐藏敏感值；包含明文敏感值必须由用户明确选择。
- 外层字段固定为 `service`、`data`、`redacted_paths`；`data` 包含默认值 `defaults` 和具名环境覆盖 `environments`。脱敏值为 `null`，`redacted_paths` 用相对于 `data` 的 JSON Pointer 指明隐藏边界；普通真实 `null` 无标记，敏感容器只报告自身边界，不展开内部路径。
- 只导出对象当前保存的原始层级，不把默认值合并进环境层，不补出缺失覆盖键或增加环境导出模式。Go `ExportJSON` 反映当前内存模型，CLI 导出取重新打开的磁盘内容；保留 JSON 类型、数值精度和数组，不附带内部分类表。
- 导出内容不能包含解锁口令或加密密钥。
- 明文导出文件已不受 vault 加密保护；文件权限、传播范围和使用后的清理由操作者负责。
- JSON 导出是查看能力，不承诺导入、备份恢复或与 vault 文件双向转换。

未指定文件时输出可读的纯 JSON 到标准输出，诊断写标准错误。指定文件默认不覆盖，仅显式选择时可覆盖，但不能把工具管理的输出指向本次输入的 vault 或凭据文件。先完整验证和准备输出，再打开输出目标；输出 I/O 失败诚实报告，不增加事务恢复或锁机制。shell 自行重定向不受程序的覆盖检查保护。

显式包含敏感值时不额外提示确认，输出真实值且 `redacted_paths` 为 `[]`，不修改原配置或分类。格式、示例与错误边界见[JSON 查看与导出契约](issues/06-json-export.md#answer)。

## 文件写入与手动复制

### 本机写入

写操作先在目标同目录生成完整的加密临时文件，检查写入、刷新和关闭结果，再尝试系统文件替换，不原地截断正式 vault，也不写明文临时文件。不把这描述成跨平台文件系统级原子事务。

修改和复制由操作者串行安排，不自动协调并发写者，不要求旁路锁文件、读写锁或复杂提交状态模型。写入错误如实返回，不自动重试或回滚；替换阶段失败时不声称原文件绝对未动，应重新打开核对。

读路径只返回完整认证的配置或明确错误，不以部分数据或空配置替代成功；完成密文读取后关闭文件句柄，既有内存快照不自动改变。普通文件权限由部署方配置，不额外引入文件系统白名单、跨账户授权或 ACL 自动修复机制。完整边界见[Vault 与解锁凭据的便携使用契约](issues/05-file-operations.md#answer)。

### 主机间分发

操作者复制加密 vault 与独立解锁凭据到新主机，待复制完成并确认运行账户有访问权限后，再通过 CLI 或 Go 程序打开或显式重新加载。不要求受控安装或注册命令，不依赖源主机绝对路径、账户标识或系统钥匙链；不在文件被读写期间直接覆盖。程序使用的内存快照保持不变。

同一时间只在一台主机编辑是操作约定，不是跨主机分布式锁。产品不自动同步、合并分歧或判断哪个副本最新。可正常解锁的旧文件仍可被使用；检测陈旧副本和防止重放旧文件不在当前承诺内。

写入完整性保护不产生可供用户查询的配置历史，也不提供回滚功能。

## 文件格式与兼容性

文件直接使用 age v1 二进制格式，只支持唯一 scrypt stanza 和固定档位 18，不作为通用 age、ASCII armor、机器密钥或插件读取器。派生前检查工作因子恰为 18，并显式设置解密最大工作因子为 18；不接受更弱或更昂贵档位，不自动降级。

内部载荷为无压缩 UTF-8 JSON，外层必须且只含 `schema_version`、`service`、`defaults`、`environments`、`classifications`；版本为整数 `1`。分类表以逻辑 JSON Pointer 为键、以 `sensitive` 或 `non-sensitive` 为值，保留缺失和类型遮挡路径的标记；现存非根配置节点必须可确定分类，数组内部不单独分类。自动结构节点只在原先未分类时记录非敏感状态，不能覆盖既有敏感标记。

拒绝未知版本、未知外层字段、未知分类值、重复字段或第二个 JSON 值，不通过格式猜测或自动迁移继续读取。完整字段和语义约束见[协议结论](issues/04-encrypted-file-format.md#answer)；格式版本不表示配置历史。

应用限制为加密文件最多 20 MiB、完整解密载荷最多 16 MiB、JSON 对象/数组最多 64 层（载荷外层为第 1 层）、分类路径最多 64 段。age 基线实现另有 2 MiB 头部上限。单次 scrypt 主工作区约 256 MiB，另有辅助及进程开销；约 1 秒是参考主机目标，不是耗时或总内存承诺。

按实际读取字节限长，派生前拒绝不支持的格式和成本档位；将明文仅暂存于内部有界内存。读至真实 EOF 并完成所有认证后，才校验载荷和一次性交付配置；不把限长制造的 EOF、部分明文或 age 的惰性 Reader 当作已验证配置，不写明文临时文件。

错误口令、损坏或被篡改的文件、不支持的格式均应明确失败，不返回部分解密数据或默认空配置。业务错误输出不得暴露敏感值；无需承诺准确区分错误口令与密文损坏。

## 验收场景

以下为未来实现的验收要求，不代表已经运行或通过测试：

1. 将同一 vault 和独立口令文件复制到其他受支持操作系统，改变它们的路径或文件名后，以兼容程序打开并取得相同配置和敏感性信息，不需要本地注册或机器绑定状态。
2. CLI 与 Go 库针对同一环境给出一致的配置解析结果，允许 CLI 在展示时按规则脱敏。
3. 对象递归合并，数组整体覆盖，类型变化整体替换；`null` 保留，删除覆盖恢复继承。
4. 未知环境明确失败，不能意外返回其他环境的配置。
5. 敏感键在环境覆盖后仍被普通查看与默认导出隐藏；只有显式选择才导出真实敏感值。
6. 脱敏 JSON 不会被误认为完整备份；任何 JSON 导出都不包含解锁口令。
7. 错误口令、密文篡改、截断文件、未知格式版本均失败，调用方不会收到部分配置或伪造的空配置。
8. 操作者串行安排修改与复制；写入不直接截断正式文件，输入或验证失败不改动原 vault，替换阶段错误不被伪报为确定成功或原文件肯定未变。
9. 在三个操作系统上，复制完成后打开只返回完整认证配置或明确错误；既有快照不被自动改变，不承诺并发复制或断电时目标必然旧/新。
10. 非交互服务通过调用方显式提供的口令解锁；库不阻塞等待终端输入。
11. JSON Pointer 区分根与空字符串键；含点号、斜杠、波浪号和 Unicode 的键可正确寻址。根写入、数组元素访问及无效路径必须失败。
12. 缺失的中间对象可创建，已有标量或 `null` 中间节点不被隐式改为对象；错误写入不保存部分变更。冲突判断不混入其他配置层的继承值。
13. 数值 `9007199254740993` 在读写和导出中不丢失精度；不能精确完成的 Go 类型转换以及解码后重复的对象键均报错。
14. 环境名称遵循已确认的字符规则；默认配置与同名普通环境的作用域不混淆。
15. 新增未分类配置值默认敏感；自动创建的中间结构不额外遮住整个分支，整体新增对象的后代键保持默认保护。
16. 删除敏感值、恢复继承或重新写入不会取消敏感标记；只取消父对象标记不能递归解除子键保护。
17. 敏感对象或数组的普通查看不暴露内部成员、数量或结构；父级类型遮挡敏感子路径时，当前视图仍整体隐藏相应父级，读取不改变分类元数据。
18. 普通真实 `null` 与被隐藏的值通过配置外的脱敏路径信息区分；敏感容器只报告自身边界，不输出内部分类表。
19. 敏感容器下的已存在与不存在路径在普通查看中得到同样的不透明结果；明文模式及业务读取仍遵循正常路径错误规则。
20. 脱敏处理不改变原始配置快照，业务程序取得真实值而非展示占位符。
21. 每份口令的来源互斥，来源失败不回退；无人值守且未指定来源时立即失败，不等待终端输入。
22. 标准输入不能同时传配置值与口令，也不能同时传更换口令所需的旧、新口令；冲突不通过读取多行秘密来猜测解决。
23. 同一 LF 或 CRLF 单行凭据文件可被 CLI 和 Go 文件式入口一致读取，其他首尾空格保持不变；解锁核心不重复裁剪口令内容。
24. BOM、无效 UTF-8、空口令、多行或 NUL 被拒绝；文本处理不隐式归一化 Unicode。
25. 新口令交互确认不一致或旧口令验证失败时原 vault 不变；自动化使用显式来源且不额外提示。旧副本不因口令更换而失效。
26. 仅接受本协议的二进制 age v1、唯一 scrypt stanza 及固定档位 18；高低工作因子均在派生前被拒绝，不发生自动降级。
27. 超过 20 MiB 的实际加密输入、16 MiB 的解密载荷、64 层 JSON 或 64 段分类路径均失败，不交付部分配置。
28. 合法头部但末块损坏、截断或尾随数据错误时，不得先向业务调用方泄露已读取的前段配置；必须完整认证后再解析和交付。
29. schema v1 的必需字段、分类覆盖及取值被校验；未知版本、未知外层字段、重复字段、非法 UTF-8 或第二个 JSON 值不得被忽略。
30. 更换口令后新文件保留全部配置与分类信息，采用新的随机材料；新口令解锁新文件，旧副本仍遵循既定旧口令边界。
31. 服务标识、环境名称和分类表不写入明文头；观察者仍能看到公开加密参数和可推导的载荷长度，这不是隐长格式。
32. 导出保存的默认层和环境覆盖层，不展开继承；未保存的环境键不被添加，内部分类元数据不被附带输出。
33. `redacted_paths` 正确指向 `data` 内的隐藏边界，区分普通真实 `null`，不枚举敏感容器内部路径或不存在的键。
34. 默认标准输出是纯 JSON，指定文件默认拒绝覆盖；显式覆盖也不得由工具覆盖输入 vault 或凭据文件。
35. 认证、载荷或序列化失败前不生成 JSON 输出或改动输出文件；实际 I/O 失败不能被伪报为成功，明文导出不改变 vault 内容和分类。
36. Go 修改在 `Save` 前不改变磁盘，失败的单次修改不破坏原内存模型；前面成功的修改不自动回滚，保存前统一校验完整载荷。
37. 已返回的快照与 JSON 字节不受后续编辑或调用方修改返回数据的影响；默认层读原值，环境解析读有效值，删除仅处理本层显式覆盖。
38. 显式生成凭据与初始化不覆盖已有文件，不因输入失败而自动生成；生成材料不打印到输出，复制后可按同样口令规则打开。
39. CLI 作用域及来源冲突以调用错误退出，操作失败与合法 `null` 区分；标准输出/标准错误和公开错误类别符合接口契约。
40. Go 公开写入、分类和更换口令与 CLI 共用核心；一组修改显式保存一次，不为每个键重复加密，不引入隐含安装、锁或会话协议。

## 实现交接

本规格中的实现前决策已闭合；Go 库和 CLI 的代码实现见 issues 12–16，接口签名、错误和主流程见[最终接口契约](issues/07-cli-go-contract.md#answer)。不需要再扩展底层文件系统保证。

已在 Windows/amd64、Go 1.27.2 上执行 `go test ./...` 和真实 CLI smoke，覆盖初始化、层级读写、脱敏、导出、口令轮换和复制后重新打开。Linux/macOS 与其他目标组合尚未运行；跨操作系统验收仍待目标环境执行。

## 范围外

- 中央服务、托管云服务、本地 HTTP 服务或远程 API。
- 配置版本历史、回滚、自动备份恢复。
- 自动跨主机同步、冲突合并、分布式锁和旧副本撤销。
- 主机级配置覆盖、跨服务共享默认值。
- vault 内按环境或用户的访问权限隔离。
- 自动热更新和后台文件监听。
- 自动跨进程文件协调、必需的旁路锁文件和受控安装命令。
- 文件系统白名单、跨账户 ACL 管理、跨平台文件系统级原子或断电事务保证，以及复杂提交状态机。

本文记录设计而非代码实现；只有经过用户确认并在对应票据记录结论的决策，才能纳入设计基线。
